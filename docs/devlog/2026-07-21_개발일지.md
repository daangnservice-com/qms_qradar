## 오늘 한 일 요약

분쟁조정 맥락에 맞춰 **파손 판별** 탭을 크게 개편했다. ①양측(신청인·피신청인)이 낸 사진을 나눠 올려 **한 번에 비교 판정**하고, ②판정 결과에 **좋아요/나빠요 피드백**을 받고, ③결과에 대해 **묻고 답하는 챗봇**을 붙였다. 여기에 **기능별 사용량 트래킹**과, 축적한 피드백·챗봇 기록을 보는 **관리자 리뷰 화면**까지 더했다. 코드리뷰·보안리뷰로 마무리.

> 상담원(사용자)이 쓰는 기능: **파손 판별 · 양측 비교 결과 보기 · 판정 챗봇으로 물어보기 · 좋아요/나빠요 남기기**.
> 그 외 축적 데이터를 **모아 보고·삭제**하는 화면은 전부 **관리자 전용**이다(아래 별도 표기).

## 결정 사항

- **양측 비교 판정**: 신청인(파손 주장)·피신청인(반박)이 낸 사진을 **각각** 올린다. AI는 두 묶음을 한 번에 보고 파손 여부와 함께 **양측 사진 간 차이·불일치(예: 한쪽엔 보이나 다른 쪽엔 안 보임)** 를 짚는다. 사진 장수는 서버 부담을 고려해 **파당 최대 5장**.
- **피드백 개선 루프**: 결과에 👍/👎 + 코멘트를 남기면 저장해 두고, 프롬프트/모델 품질 개선에 쓴다. 지금은 **수집 + 관리자 리뷰 + 프롬프트 버전 관리**까지. (자동 재학습은 범위 밖.)
- **피드백 사진 보관**: 평상시 판별 사진은 저장하지 않는다(처리 후 삭제). **피드백을 남긴 케이스의 사진만** 비공개 저장소에 보관하고 **90일 후 자동 삭제**, **관리자만** 열람. 민감정보 노출을 시간·범위로 제한.
- **챗봇은 이미지 재첨부**: 무상태 구조라 질문할 때마다 원본 사진을 다시 붙여 AI가 **실제로 다시 살펴보고** 답한다. UI는 결과 화면 **우측 하단 플로팅 버튼**.
- **삭제는 소프트 삭제**: 방금 남긴 테스트 데이터도 바로 지울 수 있게, 하드 삭제 대신 삭제표시(tombstone) 방식으로 목록·집계에서 즉시 제외.
- **트래킹은 서버측**: "누가 어떤 기능을 몇 번 썼는지"는 각 기능이 성공한 서버에서 기록(브라우저 이탈로 유실되지 않게).

## 구현 내역

### 사용자용 (상담원이 쓰는 기능)
- **양측 분리 업로드 + 통합 비교 판정** — 신청인/피신청인 업로드 존 2개, 결과에 **양측 비교** 카드 + 파손 근거(어느 쪽 사진인지 표시) + 사진별 빨간 박스 오버레이(신청인/피신청인 구분).
- **판정 챗봇** — 결과 우측 하단 "판정에 대해 물어보기" 버튼 → 대화창. "왜 이렇게 판단했어?" 등에 사진을 다시 보고 답함. 답변별 👍/👎.
- **피드백** — 결과 하단 "이 판정이 도움이 됐나요?" 👍/👎 + 코멘트. 안내 문구: *"주신 피드백을 바탕으로 판정 품질을 업데이트할 예정이에요."*

### 관리자 전용 (상담원용 아님 — 답변/노출 금지 대상)
- **`피드백` 탭 (관리자 전용)** — 좋아요/나빠요 만족도, 프롬프트 버전별 품질, 나쁜 사례의 코멘트·사진 리뷰, **피드백 삭제**, **챗봇 질문·답변 로그 + 답변 평가 열람·삭제**.
- **`사용량` 탭 (관리자 전용)** — 화면별 접속 + **기능별 사용 횟수**(파손 판별·콜 평가·챗봇 질문·피드백 제출), 사용자별 상세.
- 위 화면·API·삭제·이미지 열람은 모두 `karla@`(ADMIN_EMAILS)만 접근. 일반 로그인 사용자는 탭이 보이지 않고 직접 접근해도 차단.

### 데이터/인프라
- BigQuery(`helpdesk_x`) 신규 테이블: `damage_feedback`, `damage_feedback_deleted`, `damage_chat_turns`, `damage_chat_ratings`, `damage_chat_deleted` — 모두 **만료 미설정**(과거 60일 자동삭제 사고 반영).
- GCS 버킷 `striped-option-493506-a7-helpdesk-x-feedback`(asia-northeast3, uniform·비공개, **90일 lifecycle**). 서비스계정엔 이 버킷의 객체 권한만 부여. 열람은 관리자 signed URL.
- 프롬프트 버전 `DAMAGE_PROMPT_VERSION`(현재 `v1`) — 피드백과 짝지어 버전별 품질 비교.

## 트러블슈팅

- **다중 이미지 업로드 시 "Failed to fetch"** — 인증 미들웨어를 지나는 요청 바디가 기본 10MB로 잘려 multipart가 깨졌다. `next.config.mjs`의 `middlewareClientMaxBodySize`를 상향해 로컬 해결. ⚠️ **프로덕션(Vercel)은 함수 자체 바디 한도(~4.5MB)가 별도** → 배포 전 브라우저→GCS 직접 업로드로 우회 필요(미해결 과제).
- **GCS 버킷 자동 생성 권한 없음** — 서비스계정에 `storage.buckets.create` 없음. 버킷을 콘솔에서 수동 생성 + 객체 권한만 부여하고, 코드는 생성 실패해도 진행하도록 완화.
