## 파손 판별 — 결정 사항

- **목적**: 상품 사진을 여러 각도(1장도 OK)로 올리면 사물 종류와 무관하게 파손 여부를 AI가 판정. 용도는 **중고거래 반품/분쟁 판정 근거**.
- **판정 결과**: **파손됨 / 정상 / 불확실** + 신뢰도 + 파손 부위·유형 설명 + 사진별 코멘트.
- **여러 장 = 한 상품의 여러 각도** → 종합 판정 1개.
- **기술**: Gemini 2.5 Flash 비전, 이미지는 **File API 업로드**(원본 해상도 유지 → 미세 손상까지, 20MB inline 제한 회피). 한 번의 호출로 전 사진 판정.
- **입력**: jpg/png/webp, 1~8장, 각 ≤10MB. HEIC는 1단계 제외.
- **처리**: 동기, 1단계 로컬(AWS/SSO 보류). 로직은 `lib/vision.ts` 순수 모듈로 격리(2단계 이식 대비).

### 왜 inline이 아니라 File API?
Gemini는 요청 전체가 20MB를 넘으면 inline 불가인데 한도가 8장×10MB(최대 80MB)라 부적합. 또 축소하면 미세한 긁힘/흠집을 놓쳐서, 원본 해상도 유지가 필요 → File API로 결정.

## 박스 정확도 튜닝 (A)

실제 파손 사진(아이폰 후면 유리 깨짐 / 액정 파손 여러 대)으로 테스트 결과, 박스가 **맞는 것도 있고 손가락·빈 공간에 잡히는 것도** 있었음. 무료 레버부터 적용:

- **`temperature=0`** — 좌표 안정화.
- **타이트 박스 지시** — 손·배경·상품 전체가 아니라 실제 손상 지점만 감싸도록.
- **불확실하면 `box=null`** 강한 지시 — 부정확한 박스보다 없는 편이 안전(분쟁 오해 방지).

### 한계 / 후속 레버
- Gemini 바운딩 박스는 **근본적으로 근사값**. A로 엉뚱한 박스는 줄지만 미세 균열 픽셀 정확은 어려움.
- 더 필요하면: **B. 2단계 검출**(부위별 집중 호출로 박스만 재검출 — 정확도↑, 호출↑) → 가장 확실한 레버. **C. `gemini-2.5-pro`**(공간 인식↑, 느리고 비쌈).
- 현재는 A 적용 후 실사용 테스트 → 부족하면 B 결정 예정.
