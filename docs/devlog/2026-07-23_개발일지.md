## 결정 사항

- **샘플 선택 = BigQuery 목록**: `data-proj-470202.ds_growth_culture.vw_qradar_evaluation_cases`에서 `case_content` JSON을 풀어 `genesys_conversation_id`·`상담이력 ID`·`상담이력`을 목록으로 보여주고, 고른 통화의 conversation_id로 녹취를 확보한다.
- **로컬 업로드 완전 교체**: `UploadForm`/`UploadDropzone` 제거. 입구는 샘플 목록 하나로 단일화.
- **Genesys는 배치 방식**: 단건(GET recordings) 대신 `POST /api/v2/recording/batchrequests` → 잡 폴링 → `resultUrl`. 이유는 **아카이브(장기보관)된 녹취의 복원까지 Genesys가 처리**해줘서(우리 샘플은 2026-04~로 일부 아카이브 가능) + 대량 확장이 쉬워서. 아미르 스크립트와 동일한 흐름.
- **오디오 포맷 정규화**: Genesys 녹취(WEBM 등)를 Gemini가 보장하지 않으므로, 이미 의존성인 `ffmpeg-static`으로 **wav(16kHz mono)로 트랜스코딩** 후 무음분석·Gemini 업로드에 모두 사용.
- **접근 제어 유지**: 콜 품질 평가는 계속 **karla 단독**(`isKarla`). 목록·평가 API 모두 서버측 가드.
- **자격증명은 env로만**: Genesys client_id/secret은 코드 하드코딩 없이 env 주입. (참고 레포엔 하드코딩·노출돼 있어 로테이션 권장.)

## 구현 내역

### 사용자용 (karla)
- **평가 샘플 목록** — `SampleList` 컴포넌트가 `/api/call-quality/samples`를 불러 표(상담이력 ID · conversation_id · 연월 · 상담이력 미리보기) + 행별 "평가" 버튼으로 렌더. 공백 감지 기준 슬라이더 유지, 결과는 기존 `ResultView` 재사용.
- **평가 실행** — "평가" 클릭 → `POST /api/evaluate {conversationId, minSilenceSec}` → 서버가 Genesys 배치로 녹취 URL 확보 → 다운로드 → wav 변환 → 무음분석 + Gemini 채점·전사 → 결과 표시.

### 서버/라이브러리
- **`lib/genesys.ts`(신규)** — OAuth(client_credentials, 토큰 메모리 캐시) + **배치 흐름**: `createBatchRequest`(표준 `batchDownloadRequestList`부터 스키마 변형 순차 시도) → `waitForBatch`(완료/URL 확보까지 폴링, 대기 기본 180초·`GENESYS_MAX_WAIT_MS`로 상향) → `extractUrls`로 resultUrl 추출 → `downloadAudio`.
- **`lib/evaluationSamples.ts`(신규)** — 기존 `getBQ()` 자격증명 재사용, `data-proj-470202` 뷰를 **교차 프로젝트** 쿼리. location은 강제하지 않고 auto-detect(필요시 `GROWTH_CULTURE_LOCATION`).
- **`app/api/call-quality/samples/route.ts`(신규)** — karla 가드 + 목록 반환.
- **`app/api/evaluate/route.ts`** — 입력을 FormData(file) → **JSON `{conversationId}`**. Genesys 확보 → wav 변환 → 평가. `maxDuration` 300(EC2 상주 기준).
- **`lib/audio.ts`** — `transcodeToWav` 추가. **`lib/gemini.ts`** — 업로드 mimeType `audio/wav`로.
- 삭제: `components/UploadForm.tsx`, `components/UploadDropzone.tsx`.

## 트러블슈팅 / 메모

- **BigQuery가 다른 프로젝트/리전** — 뷰가 앱 프로젝트(`striped-option-…`)가 아닌 `data-proj-470202`(데이터팀 소유)라 **교차 프로젝트 접근**. 앱 서비스계정 `google-group-checker@…`에 `ds_growth_culture` **dataViewer** 권한이 있어야 하며, 이는 데이터 프로젝트 오너(아미르)만 부여 가능. 리전 값도 아직 미확인 → 우선 auto-detect.

- **참고 레포 secret 노출** — `genesys_recording_downloader/recording_download_links.py` 36–37줄에 client_id/secret 하드코딩. 우리 앱은 env로만 받되, 값 자체는 로테이션 필요.

## 코드리뷰 반영 (배치 흐름 `lib/genesys.ts`)

배치 전환 직후 `/code-review`(high)로 배치 흐름을 점검, **5건 모두 수정**. 대부분 "실데이터 붙기 전엔 안 드러나지만 실동작 시 바로 터질" 것들이라 선반영.

- **완료/실패 판정을 count 기반으로 재작성** — Genesys `batchrequests` 응답엔 top-level `status`가 없고 `resultCount`/`expectedResultCount` + 항목별 `resultUrl`/`errorMsg`로 완료를 알린다. 기존 status 의존 로직은 실패를 아예 감지 못 해 **없는 녹취도 180초 폴링 후 "복원 중, 재시도" 오안내**를 냈다. → `isBatchComplete()`로 판정하고, `errorMsg`가 있으면 **영구 실패로 즉시 안내**.
- **전 항목 완료까지 대기** — 첫 항목 URL이 뜨자마자 반환하던 걸 고쳐(대량 확장 시 미준비 건 누락 방지), 모든 요청분이 URL/에러로 종결된 뒤 반환.
- **폴링 중 일시 오류 재시도** — 429/5xx는 치명 처리하지 않고 재시도(한 번의 rate limit로 평가 전체가 죽지 않게).
- **바디 스키마 폴백 확장** — 변형 재시도 조건을 400 → 400/415/422로.
- **`GENESYS_MAX_WAIT_MS` 클램프** — 음수/NaN이면 기본 180초로(폴링이 통째로 건너뛰어지는 foot-gun 제거).
- 신규 순수함수 `isBatchComplete`/`batchErrorMessages`에 단위 테스트 추가(회귀 방지).
