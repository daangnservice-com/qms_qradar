- **BigQuery: 뷰 → 실물 테이블**: 레퍼런스 뷰가 권한 없는 원본 데이터셋(`karrotmarket.db_karrot_cs_kr` 등)을 참조해 SA 조회가 막히던 문제를, DA가 `data-proj-470202.ds_growth_culture.**qradar_evaluation_cases**`(실물 테이블)로 해소. 리전 **US**(`GROWTH_CULTURE_LOCATION=US`), SA `google-group-checker@`에 dataViewer. 파티션/증분용 `inquiry_created_at_kst` 컬럼 추가됨.
- **Genesys 확보: 배치 → 단건(직접)**: 배치(`/recording/batchrequests`)는 `fileState=AVAILABLE` 녹취에도 잡이 **~3분 InProgress**로 매우 느렸다. AVAILABLE 녹취는 실시간 recording API(목록 → 상세 `download=true`)로 **수 초** 안에 미디어 URL을 받는다. 배치는 아카이브 복원/대량 폴백(`getConversationAudioUrlViaBatch`)으로만 남김.
- **통화당 dedup**: 한 통화(conversation_id)가 여러 상담이력 케이스에 묶여 중복 → `qualify row_number()`로 통화당 최신 1건만.
- **통화 길이**: `case_content`의 `call_start`/`call_end` 차이(우선), 없으면 `minutes_taken`(폴백).
- **결과 UX = 오른쪽 슬라이드 패널**: 결과가 목록 밑에 쌓이지 않고, 평가 완료 시 "평가 완료" 토스트 + 오른쪽 패널이 슬라이드로 열림. 완료 상태는 conversationId별로 보관해 다른 항목을 평가해도 유지.

## 오늘 오후 한 일 요약
오전(1부)에 실데이터 end-to-end를 뚫은 데 이어, 오후엔 **도구의 성격 자체를 "평가"에서 "분석"으로 재정의**하고 실사용에 필요한 것들을 한 번에 붙였다. ①샘플을 **검색/필터**로 골라, ②**조직 탭(성장문화실/페이팀)** 별로 권한·결과 저장소를 분리하고, ③결과를 **BigQuery에 영구 저장 + 사내 공유 URL** 로 남기고, ④전사·타임스탬프를 **Gemini 추정 → Google STT 실측**으로 바꿔 정확도를 확보(듀얼채널 **화자분리** 포함)하고, ⑤스크립트 시각을 누르면 **실제 오디오 위치로 재생**(다운로드는 차단)되게 하고, ⑥스크립트·총평·코멘트에 **PII 마스킹**을 걸었다.

## 결정 사항
- **"평가" → "콜 분석"으로 리네이밍(UI 텍스트)** — 점수 매김이 아니라 통화를 뜯어보는 도구로 성격 재정의. 내부 심볼(`CallQualityEval` 등)은 유지, 사용자 노출 문구만 "분석"으로.
- **조직 탭 분리** — `성장문화실`(`/call-quality`) · `페이팀`(`/call-quality/pay`). **접근 권한 분리**: 성장문화실 = karla·laika·amir·riley.lee(`CALL_QUALITY_EMAILS`), 페이팀 = karla·taeo·heather(`PAY_CALL_QUALITY_EMAILS`). **결과 저장 테이블도 분리**(아래). 샘플 소스는 공통, 조직별 채점 기준 분기는 **페이팀 기준 확정 대기로 보류**.
- **결과 영구 저장 = BigQuery** — `data-proj-470202.ds_growth_culture.qradar_evaluation_results`(성장문화실)/`qradar_evaluation_results_pay`(페이팀). SA에 **dataEditor**. 분석하면 목록에 "분석 완료"가 세션 넘어 유지되고, `[결과 보기]`(저장본 재조회)·`[재분석]` 제공.
- **결과 공유 URL** — `/call-quality/result/[id]` 사내 공유 링크(조직 무관 `getAnalysisById`가 양 테이블 검색). 링크만 있으면(권한 계정) 저장된 분석을 그대로 열람.
- **전사·타임스탬프 = Google STT(실측), 채점 = Gemini** — Gemini는 긴 통화에서 시간을 **압축 추정**(20분 통화의 02:00이 실제 03:22)해 seek이 어긋났다. → **Speech-to-Text `longRunningRecognize`(GCS 입력)** 로 전사·워드 타임스탬프를 실측하고, Gemini는 **채점 + 상담원 화자 판별(`agentSpeakerTag`)** 만.
- **화자분리 = 듀얼채널** — ko-KR diarization은 전부 한 화자로 뭉개져 실패 → Genesys 녹취가 **좌우 채널로 상담원/고객이 물리 분리**된 점을 이용, 스테레오 WAV + `enableSeparateRecognitionPerChannel`(`channelTag`=화자)로 정확 분리. 태그 2종 이상일 때만 상담원/고객 라벨(오분류 방지).
- **무발화 공백 = STT 기반** — 양 채널이 다 조용한 구간(발화 구간 합집합의 사이)을 공백으로 계산. **보류음이 깔린 1분 공백**처럼 ffmpeg 무음이 놓치던 것도 잡음. ffmpeg 무음은 STT 실패 시 폴백.
- **음성은 임시 재생만, 다운로드 차단** — 프록시 스트리밍 + `controlsList=nodownload` + 우클릭 차단(UI 레벨).
- **PII 마스킹(표시+저장)** — 전화·주민번호·카드·이메일. 저장 전 마스킹(BQ에 원본 X) + 표시 시 마스킹(기존 저장분도 즉시 가림), **멱등**이라 이중 적용 안전.

# ▣ 3부 (같은 날, 저녁) — CS 영역 체크리스트 (성장문화실 품질기준 AI 판별)

주제: **성장문화실 품질평가 기준을 AI가 항목별로 판별 — CS 영역 20개 위반 체크리스트(근거 강제) · 성장문화실 전용 · 3점 채점/총평 대체**

> ⚠️ **관리자 전용.** **@헬비**: 규칙12대로 상담원 안내 금지(confidence "none").

## 오늘 저녁 한 일 요약
성장문화실에서 받은 **CS 직무 판별기준(37개)** 을 AI 콜 분석에 붙였다. 다만 전부가 아니라, **오디오·전사만으로 판별 가능한 [CS 영역] 20개**로 스코프를 잡았다(기준표 비고 "AI 평가는 일단 CS 영역만"과 일치). 방식은 **점수 매김이 아니라 "항목별 위반 여부 + 근거(전사 인용·시각) 강제"** 로 바꿔 환각을 통제했다. 성장문화실 결과 화면은 **기존 3점 채점·총평을 걷어내고 체크리스트를 중심**으로 재구성했다.

## 결정 사항
- **범위 = [CS 영역] 20개만.** 직무 영역(정확응대·설명능력·절차준수·리스크관리)·**중대 오안내는 정책 지식/CRM 히스토리가 있어야** 판별 가능 → AI 환각 위험이라 **제외**(추후 지식베이스 연동 시 별도).
  - CS 영역 안에서도 [문의 파악] 일부(424·426·652·430·425·420)는 정답/이력 의존이라 **신뢰도 낮음** → "근거 강제 + 애매하면 false"로 통제하고, **사람 평가 대비 일치율로 재보정** 예정.
- **점수 → 위반 체크 + 근거 강제.** 각 항목 `violated`는 **전사 인용문(quote)+시각(atSec) 근거가 있을 때만** true. 근거 없으면 false, **애매하면 false**(과잉지적 금지).
- **성장문화실(growth) 전용.** org를 프롬프트·**응답 스키마까지** 관통시켜 growth일 때만 체크리스트를 요구. **페이팀(pay)은 미적용**(기준 확정 대기) — 스키마에서 아예 빠져 모델이 억지로 채우지 않음.
- **성장문화실 결과 화면 = 체크리스트 중심.** growth는 **3점 채점 카드·총평 숨김**(에러는 계속 표시), 체크리스트는 **"이상 없음"까지 펼친 상태로 고정**. pay는 기존 3점 채점·총평 유지.
- **id = `evaluation_criterions_id`.** 당근서비스워크 평가폼 체크박스와 **1:1 매핑** — 추후 자동기입 연동 키로 사용.
- **근거 인용도 PII 마스킹.** evidence quote·reason도 전사에서 온 것이라 저장·표시 양쪽 `maskPII`.
- **비용 증분 ≈ 0.** 별도 AI 호출 없이 **기존 Gemini 채점 호출에 얹음**. 항목 10→20 확대도 출력 토큰 몇백 개(≈0.3센트)뿐 — 비용은 STT(오디오)가 지배하므로 항목 수와 무관.

## 구현 내역
- **`lib/csChecklist.ts`(신규)** — CS 영역 20개 기준(id·대분류·라벨·판별 힌트) + `buildChecklistPromptBlock()`(근거 강제 규칙, 항목 수 동적).
- **`lib/gemini.ts`** — `buildEvaluationPrompt(...,checklist)`·`buildResponseSchema(checklist)`로 **프롬프트·스키마 조건부**, `runGeminiEvaluation(...,{checklist})`, 파싱에 `csChecklist` 추가.
- **`lib/evaluate.ts`** — `opts.org`로 `checklist = org==="growth"` 판정, 근거 인용 PII 마스킹.
- **`lib/types.ts`** — `Evaluation.csChecklist?`(구버전 저장분 호환 optional), `ChecklistResult`.
- **`app/api/evaluate/route.ts`** — `evaluateFile`에 `org` 전달.
- **`components/ChecklistView.tsx`(신규)** — 위반 항목(근거 타임스탬프+인용) + 이상없음 항목 펼쳐 표시.
- **`components/ResultView.tsx`** — growth/pay 분기(성장문화실은 채점·총평 숨김), 체크리스트 표시.
