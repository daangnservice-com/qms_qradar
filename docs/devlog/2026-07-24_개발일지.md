## 오늘 한 일 요약

어제 골격을 만든 콜 품질 평가(**관리자 전용**)를 **실데이터로 처음부터 끝까지 동작**하게 마무리했다. DA가 권한 문제로 뷰 대신 **실물 테이블**을 만들어줘 BigQuery 조회가 뚫렸고, Genesys 녹취 확보를 **배치 → 단건(직접)** 으로 바꿔 속도를 확 줄였다(3분 → 수십 초). 목록에 **통화 길이**를 표시하고, 결과를 하단 스택이 아니라 **오른쪽 슬라이드 패널**에서 보도록 UX를 개선했다.

## 결정 사항

- **[관리자 전용]** 콜 품질 평가 페이지(`/call-quality`)·API·샘플 목록은 계속 **karla 단독**(`isKarla`). 일반 상담원에게 노출·안내하지 않는다.
- **BigQuery: 뷰 → 실물 테이블**: 레퍼런스 뷰가 권한 없는 원본 데이터셋(`karrotmarket.db_karrot_cs_kr` 등)을 참조해 SA 조회가 막히던 문제를, DA가 `data-proj-470202.ds_growth_culture.**qradar_evaluation_cases**`(실물 테이블)로 해소. 리전 **US**(`GROWTH_CULTURE_LOCATION=US`), SA `google-group-checker@`에 dataViewer. 파티션/증분용 `inquiry_created_at_kst` 컬럼 추가됨.
- **Genesys 확보: 배치 → 단건(직접)**: 배치(`/recording/batchrequests`)는 `fileState=AVAILABLE` 녹취에도 잡이 **~3분 InProgress**로 매우 느렸다. AVAILABLE 녹취는 실시간 recording API(목록 → 상세 `download=true`)로 **수 초** 안에 미디어 URL을 받는다. 배치는 아카이브 복원/대량 폴백(`getConversationAudioUrlViaBatch`)으로만 남김.
- **통화당 dedup**: 한 통화(conversation_id)가 여러 상담이력 케이스에 묶여 중복 → `qualify row_number()`로 통화당 최신 1건만.
- **통화 길이**: `case_content`의 `call_start`/`call_end` 차이(우선), 없으면 `minutes_taken`(폴백).
- **결과 UX = 오른쪽 슬라이드 패널**: 결과가 목록 밑에 쌓이지 않고, 평가 완료 시 "평가 완료" 토스트 + 오른쪽 패널이 슬라이드로 열림. 완료 상태는 conversationId별로 보관해 다른 항목을 평가해도 유지.

## 구현 내역 (전부 관리자 전용 기능)

- **`lib/genesys.ts`** — 단건 직접 흐름(`listRecordings` `download=false`로 fileState 확인 → `getRecordingMediaUrl` `download=true` 202 폴링 → `extractUrls`). 아카이브(ARCHIVED/RESTORING)면 즉시 "복원 필요" 실패. 배치는 폴백 함수로 분리.
- **`lib/evaluationSamples.ts`** — 실물 테이블 조회, `inquiry_created_at_kst` 정렬, 통화당 dedup, `call_start/call_end/minutes_taken`로 통화 길이 계산.
- **`components/ResultDrawer.tsx`(신규)** — 오른쪽 슬라이드 결과 패널(ESC·배경·X로 닫기).
- **`components/SampleList.tsx`** — 통화 길이 배지(⏱ MM:SS), "평가 완료" 토스트, 완료 행 "결과 보기", 완료 상태 유지.
- **`components/CallQualityEval.tsx`** — 결과를 conversationId별 맵으로 보관 + 패널 연결.
- **`app/api/evaluate/route.ts` / `lib/evaluate.ts`** — 단계별 처리시간 측정 로그.
