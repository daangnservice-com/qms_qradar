## 결정 사항

- **ALB idle timeout 상향(인프라 요청) 대신 스트리밍 선택.** idle timeout은 "총 처리 시간"이 아니라 **"아무 바이트도 안 오간 시간"** 기준이라, 처리 중 주기적으로 이벤트를 흘려보내면 타이머가 계속 리셋된다. **인프라 변경 없이 코드만으로 해결**되고, 통화 길이가 얼마든 상관없어진다.
- **검증(401/403/400)은 스트림을 열기 전에.** 스트림은 200이 먼저 나가 상태코드에 실패를 실을 수 없다. 권한·입력 오류는 기존처럼 상태코드로, **처리 중 실패는 스트림 안의 `error` 이벤트**로 구분해서 보낸다.
- **`Cache-Control: no-transform` 필수.** Next의 gzip 압축이 청크를 모아버리면 하트비트가 묻혀 idle timeout을 못 피한다. 압축 미들웨어는 `no-transform`을 보면 압축을 건너뛴다. `X-Accel-Buffering: no`도 같이 넣어 nginx류가 앞단에 붙어도 버퍼링되지 않게 했다.
- **비동기 잡(잡 큐 + 폴링)은 다음 단계로.** 스트리밍으로 타임아웃 자체는 해소되지만 **브라우저 탭을 닫으면 결과를 못 받는다**(서버 처리는 끝나서 BigQuery에는 저장됨). 결과 영구저장·`/api/call-quality/results`가 이미 있어 절반은 만들어져 있고, **대량 배치 평가**를 붙일 때 어차피 필요하므로 그때 함께 하기로.

## 구현 내역 (전부 관리자 전용 기능)

- **`app/api/evaluate/route.ts`** — 응답을 NDJSON 스트림으로 전환. 단계별 `progress`(genesys → download → transcode → analyze → save) + **5초 간격 `heartbeat`** → 마지막에 `result` 또는 `error`. 클라이언트가 끊겨도 전송만 멈추고 처리·저장·임시파일 정리는 그대로 끝낸다. 효과 없는 `maxDuration` 제거(주석으로 이유 남김).

- **`lib/types.ts`** — `EvaluateEvent`/`EvaluateStep` 타입 추가(서버·클라이언트 공용).
- **`components/SampleList.tsx`** — 스트림을 읽어 **진행 단계 + 경과 초**를 표시("전사·채점 중 (가장 오래 걸려요)… 87초 경과"). 스트림이 `result` 없이 끝나면 연결 끊김으로 보고 안내.
- **`lib/apiError.ts`** — Vercel/60초/4.5MB 문구를 현행화. 업로드 한도는 미들웨어 110MB 기준이라 413 문구도 실제에 맞게 수정.

# ▣ 2부 (같은 날) — 긴 통화(40분급) 대비: Gemini 파일 대기 상한 상향

## 배경

스트리밍으로 **연결이 끊기는 문제는 해소**됐지만(통화 길이 무관), 40분급 통화는 **연결이 아닌 내부 한도**에 걸릴 수 있다는 걸 확인했다. `lib/gemini.ts`의 파일 ACTIVE 대기 상한이 **120초(60회 × 2초)** 였는데, 40분 통화의 mono wav는 약 **77MB**라 이 안에 처리되지 않을 여지가 있었다.

하필 이때 뜨는 메시지가 **"더 짧은 파일로 시도해 주세요"** 여서, 방금 고친 타임아웃 안내와 혼동될 소지도 컸다.

## 변경

- **`lib/gemini.ts`** — `MAX_POLL_ATTEMPTS` 60 → **150** (× 2초 = **300초**). 정상 파일은 금방 ACTIVE라 **평소 대기 시간은 늘지 않는다**(상한만 올라감).
- 에러 메시지에서 **"더 짧은 파일로 시도해 주세요" 문구 삭제**. 40분 통화를 정상 사용하는 상황에서 "짧게 하라"는 건 잘못된 처방이라, 원인만 알리도록 정리.
- `lib/geminiFiles.ts`의 **이미지 대기 상한(30초)은 그대로**. 파손 판별 경로라 콜 분석과 무관하고 이미지엔 충분하다.

## 40분 통화 소요 시간 추정 (실측 전)

| 단계 | 40분 추정 | 근거 |
|------|-----------|------|
| Genesys 녹취 확보 | ~10초 | 통화 길이 무관 (07-24 실측 9.7초) |
| 다운로드 | 수 초 | Opus 40분 ≈ 20~40MB |
| 트랜스코딩 ×2 + 무음분석 | ~20초 | mono(Gemini용) + stereo(STT용) 2회 |
| GCS 업로드(STT용) | 10~40초 | stereo 16kHz 16bit = **154MB** |
| **STT** | **~90초** | 07-24 실측 "42분 ≈ STT 90초" |
| Gemini 업로드 + ACTIVE 대기 | 30~120초 | mono wav **77MB** ← 이번에 상한 300초로 상향 |
| **Gemini 채점** | **1.5~3분** | 2분 통화 41초, 오디오 입력 ≈ 76,800토큰 |

→ **총 4~7분(중앙값 5분 안팎)** 추정. 전사는 STT가 하고 Gemini는 채점·코멘트만 출력하므로 **출력 길이가 통화 길이에 비례하지 않아**, 20배 통화가 20배 시간이 되지는 않는다.

## 남아 있는 위험(미해소)

- **Gemini 채점 호출이 5분을 넘는 경우** — Node HTTP 클라이언트 기본 헤더 타임아웃(300초)에 걸릴 여지. 실제로 걸리는지 봐야 손댈 수 있어 일단 관찰만.
- **임시파일 230MB+** — 원본 + mono 77MB + stereo 154MB가 `/tmp`에 동시 존재(처리 후 정리됨). 컨테이너 디스크 여유 확인 필요.
- **아카이브 녹취**는 통화 길이와 무관하게 즉시 실패(기존 이슈).

# ▣ 3부 (같은 날) — 스크립트 스크롤 UX · 팀 안내 문서 보강

## 전체 대화 스크립트: 중첩 스크롤 제거 + 플레이어 고정

사용자 피드백: **스크립트가 "안쪽"에서 스크롤돼 불편**하다. 결과 패널(바깥)과 스크립트 카드(안쪽)가 각자 스크롤을 갖는 **중첩 스크롤** 구조라, 마우스 위치에 따라 어느 쪽이 움직일지 예측이 안 됐다.

- **`components/Transcript.tsx`** — 스크립트 목록의 `max-h-96 overflow-y-auto` **제거**. 전부 펼치고 스크롤은 **바깥(패널/페이지)에서 한 번만** 일어나게 했다.
- 대신 스크립트를 길게 펼치면 위에 있던 **오디오 플레이어가 화면 밖으로 사라지는** 문제가 생겨, 플레이어를 `sticky top-0 z-10 bg-white`로 **상단 고정**. 시각을 눌러 이동하며 들을 때 재생 컨트롤이 항상 보인다.
- 스크립트는 기본 접힘 상태라 펼치기 전 화면 길이에는 영향 없음. sticky를 막는 `overflow: hidden` 조상 요소가 없는 것도 확인.
- 앱에 남은 내부 스크롤은 필터 다중선택 드롭다운 하나뿐(정상 용도).

**적용 범위**: 성장문화실(`/call-quality`)·페이팀(`/call-quality/pay`)이 **같은 컴포넌트 트리**(`CallQualityEval → ResultDrawer → ResultView → Transcript`)를 쓰고 `org`는 권한·결과 테이블 분기에만 관여하므로, UI 변경은 **양 조직 탭 + 공유 URL 전체 화면(`/call-quality/result/[id]`) 모두에 동시 반영**된다.

## 팀 안내 문서(`docs/팀_안내.md`) — 당근알바팀·광고팀 추가

@헬비의 **팀 라우팅**("이 문의 어느 팀?") 근거 문서라, 이 파일을 push하면 매시간 동기화로 답변에 반영된다.

- **당근알바팀 신설** — 빠른 안내 표 + 팀별 상세. 담당 영역: 레슨/과외, 알바 구인광고 및 승인, 구인자 글기간권 세금계산서, 구인구직 시 사업자/본인인증, 구인자 광고 캐시충전·환불·성과, 구인자 이용 방법, 공고 작성 방법, 채용 관련, 구인자 광고 필수 업종(유료 카테고리), 구인자 충전·환불.
- **광고팀 신설** — 광고 심사(주 업무)·광고주 대응. 팀에서 준 소개문을 문서 톤에 맞춰 반영.
- **⚠️ 라우팅 충돌 해소** — 기존 표에 `광고·비즈프로필 등 로컬비즈 사업자 관련 → 로컬비즈니스팀` 행이 있어 **광고 심사 문의가 로컬비즈니스팀으로 안내**될 상태였다. 표를 `광고 심사·광고주 대응 → 광고팀` / `비즈프로필 등 로컬비즈 → 로컬비즈니스팀` 두 줄로 분리하고, 로컬비즈니스팀 상세 설명에서도 "광고와 비즈프로필을 중심으로" → **"비즈프로필을 중심으로"** 로 수정.
- 이제 광고 심사=광고팀 / 비즈프로필=로컬비즈니스팀 / 구인광고=당근알바팀으로 겹침 없이 갈린다.

> 당근알바팀 소개 문단은 담당 영역에서 유추해 쓴 문장이다(다른 팀은 실제 팀 소개문). 팀 공식 소개문이 오면 교체 필요.
