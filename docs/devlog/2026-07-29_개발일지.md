## 원인 분석

- `app/api/call-quality/filter-options/route.ts`가 `canAccessCallQuality`(= `CALL_QUALITY_EMAILS`, **성장문화실** 목록)로 가드하고 있었다. 반면 샘플 목록 API(`samples/route.ts`)는 `canAccessOrg(org, …)`로 **조직별** 가드를 쓴다.
- 그 결과 **페이팀 전용 계정(taeo·heather)** 은 샘플 목록은 정상인데 **필터 옵션만 403** 을 받았다. (karla·amber.jeon은 양쪽 목록에 다 있어 재현되지 않는다 — 제보자 계정에 따라 증상이 갈리던 이유.)
- 프론트(`components/FilterPanel.tsx`)는 `r.ok ? … : null` + `.catch(() => {})` 로 실패를 **조용히 삼켜서**, `options`가 초기값 `{teamAgents: [], categories: []}` 그대로 남았다 → 팀·닉네임·카테고리 **드롭다운 3개가 전부** 빈 상태 → `MultiSelect`의 빈 상태 문구 **"값이 없어요"**.
- 같은 라우트의 catch 폴백도 문제였다. `200 + { teams: [], categories: [], adminNames: [] }` 를 돌려주는데, **클라이언트가 읽는 키는 `teamAgents`** 라 키 이름도 안 맞았다. 즉 **BigQuery 쿼리가 죽어도 화면 증상이 완전히 동일**해서 원인 분리가 불가능했다.

> 참고: 필터 옵션은 `data-proj-470202.ds_growth_culture.qradar_evaluation_cases`의 `case_content.$.operator_renewal_team_name` distinct다. 07-24에 정한 대로 **샘플 소스는 조직 공통**이므로, 페이팀 탭이라고 팀 목록이 달라지지 않는다 → 옵션 API를 조직별로 가드할 이유 자체가 없었다.

## 결정 사항

- **가드는 완화, 제거는 아님.** `canAccessCallQuality` → **`canAccessAnyCallQuality`**. 콜 분석 **어느 탭이든** 접근 권한이 있으면 옵션 조회를 허용한다. 옵션 자체가 조직 공통 데이터이고 팀명·닉네임·카테고리 목록뿐이라 조직별로 나눌 실익이 없다. 로그인·화이트리스트 자체는 그대로 유지(비허용 계정은 여전히 403).
- **대안이었던 "`?org=` 받아 `canAccessOrg`로 분기"는 안 씀.** 옵션이 공통인데 파라미터만 늘어나고, 페이팀 계정이 성장문화실 팀명을 못 보게 막는 것도 의미가 없다.
- **실패는 500으로 드러낸다.** `200 + 빈 옵션` 폴백을 없앴다. "옵션이 진짜 없음"과 "조회가 깨짐"이 화면에서 같아 보이면 안 된다.
- **프론트도 실패를 표시.** 배너로 알리되 **패널은 계속 열어둔다** — ID 입력·날짜·통화시간 필터는 옵션 없이도 쓸 수 있으므로 전체를 막지 않는다.

**진단 전(07-29 오전)** — `last_modified = 2026-07-24T01:40:43Z`(KST 10:40)에서 멈춤. 07-25~07-29 **0건**, 07-24도 UTC 01:29(KST 10:29)까지만 들어와 40건. **`cid_null`·`ym_null`은 전 구간 0** 이라 앱 조건(`genesys_conversation_id is not null`, `year_month >= '2026-04-01'`)은 무죄로 확정됐다. `call_start` null 행도 0건이라 집계에서 새어나간 것도 없음.

## 알게 된 것

- **`call_start`는 UTC다.** 원문이 `2026-07-24T01:29:07.706467Z`. 그런데 앱은 이 문자열 앞 10자를 그대로 날짜로 쓴다(필터 `lib/evaluationSamples.ts:76`, 목록 표시 `:129`). 업무시간(KST 09~18시) 통화는 UTC로도 같은 날짜라 평소엔 안 드러나지만, **KST 09시 이전 통화는 필터·화면 양쪽에서 하루 전날로 잡힌다.** → `datetime(timestamp(call_start), 'Asia/Seoul')` 기준으로 바꿔야 한다. (미수정, 아래 남은 것)
- **새 스케줄의 실제 지연은 10~23시간.** "매일 09시, 전날까지"라서 당일 통화는 다음날 09시에 보인다. **지금 07-29 데이터가 보이는 건 일회성 재처리 결과**이고, 내일부터 당일 통화가 안 보이는 것이 정상 동작이다 — 헷갈리기 쉬우니 팀에 공유 필요.
- **07-17(금)은 아직 미복구.** 10건 그대로다(07-16 목 487건 / 07-20 월 566건 사이). 이번 재처리 범위가 07-24 이후였던 것으로 보인다.

## 결정 사항

- **원본(`db_karrot_cs_kr`) 직접 조회는 보류.** DA가 "실시간에 가깝게 하려면 서비스계정에 원본 권한을 추가해 직접 보는 게 낫다"고 제안했으나, ①원본은 스키마가 달라 **앱 쿼리 3곳을 새로 짜야** 하고(현재는 `case_content` JSON + `year_month`·`inquiry_created_at_kst` 의존), DA 테이블이 이미 해준 "평가 대상 케이스" 가공 로직까지 앱이 떠안게 된다. ②필터 옵션의 `distinct` 쿼리가 원본을 훑으면 **스캔 비용**이 커진다. ③서비스계정 키를 **helpdesk-x 전 기능이 공유**하므로 권한 확대 = 콜 분석 외 기능의 **PII 접근 범위 확대**.
- **대신 DA에 스케줄 주기 상향(1일 1회 → 1시간)을 요청하는 방향.** 앱 코드 변경 0·권한 확대 0으로 지연만 10~23시간 → 1시간이 된다. 콜 분석은 사후 품질 분석 도구라 분 단위 실시간이 필수가 아니다.
- **단, 요청 자체는 홀딩.** 실시간성을 요구한 팀원에게 필요 수준을 먼저 확인하기로 했다(1시간 주기로 충분한지). 확인 후 07-17 재처리와 함께 요청.
- **점검 스크립트는 상설화.** 같은 증상("특정 날짜가 안 보인다")이 재발하면 한 줄로 **적재 지연 / CID null / year_month null / 타임존**을 즉시 가른다. 이번에 앱을 의심하는 데 쓴 시간이 그대로 절약된다.

### `call_start` KST 보정 (같은 날 이어서 수정)

- **`lib/evaluationSamples.ts`** — 공용 상수 2개 추가.
  ```
  CALL_START_TS = safe_cast(json_value(case_content,'$.call_start') as timestamp)
  CALL_DATE_KST = format_date('%F', date(CALL_START_TS, 'Asia/Seoul'))
  ```
  ①**날짜 필터**를 `substr(call_start,1,10)`(UTC 앞 10자) → `CALL_DATE_KST` 비교로 교체. ②**표시용**으로 `call_date_kst` 컬럼을 select에 추가하고, 매핑을 `String(call_start).slice(0,10)` → `call_date_kst`로 교체(필터와 화면 날짜가 어긋나지 않게 **같은 식**을 쓴다).
  - `safe_cast`를 쓴 이유: 포맷이 어긋난 행이 있어도 쿼리 전체가 죽지 않고 그 행만 날짜 필터에서 빠진다. **실측 파싱 실패 0건**.
- **`lib/types.ts`** — `callDateStart`/`callDateEnd`/`callDate` 주석을 KST 기준으로 갱신.
- **`lib/evaluationSamples.test.ts`(신규)** — `getBQ`를 목으로 잡고 **생성된 SQL을 직접 검증**한다: 날짜 필터에 `'Asia/Seoul'`이 들어가고 **옛 UTC 표현식이 없을 것**, 날짜 필터가 없으면 조건을 안 붙일 것, 표시용 `callDate`가 `call_date_kst`에서 올 것(+통화 길이는 절대시각 기준이라 변환과 무관함도 같이 고정).

**보정 효과(실측, 07-20~07-29)** — 하루 2~7건이 전날로 밀려 있었다. KST 00~09시 통화라 대부분 야간 콜이다. 07-28 하루로 보면 **UTC 기준 566건 → KST 기준 571건**. 규모는 작지만 "어제 야간 콜을 찾는데 안 나온다"가 재현되던 구간이다.
