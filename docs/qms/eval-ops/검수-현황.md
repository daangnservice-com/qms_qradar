# 검수 현황

평가 운영 메뉴. **AI 평가 + 수기 검수 완료**된 케이스(`call_eval` · `review_completed_at`)를 기간별로 집계한다.  
UI는 [정확도 대시보드](../eval-design/정확도-대시보드.md)와 동일 패턴을 쓴다.

## 라우트 · 권한

| | |
|---|---|
| 라우트 | `/eval-ops/review-status` |
| API | `GET /api/eval-ops/review-status?month=YYYY-MM` 또는 `startDate`/`endDate` |
| 게이트 | `canAccessCallQuality` (`CALL_QUALITY_EMAILS`) |
| 스토어 | `lib/reviewStatusStore.ts` · `lib/reviewStatusPeriod.ts` |

## 기간

- 기본: **당월**(Asia/Seoul)
- 월 선택 또는 시작~종료일(종료일 포함)

## UI 구성

1. Accuracy · Recall · Precision KPI (+ 임계 색 막대) — **검토필요 = positive**
2. FN → FP · confusion matrix (`수기 검토필요 \ AI 검토필요`)
3. **평가셋 비중** — 케이스에 쓰인 프롬프트 버전별 건수·%
4. 항목 토글 — 주로 틀리는 항목 ↔ 항목별 AI–수기 감지 비교
5. **검수 완료 케이스** 테이블  
   - 케이스: `상담사닉네임 (콜날짜)` + conversation id · 클릭 시 평가 진행 딥링크  
   - 복귀 위젯: `ReviewStatusCheckoutWidget` (프롬프트 개선 checkout과 동일 UX)  
   - 수기/AI 검토필요 뱃지 · 수기 **최종 Cold/Hot** · 검토필요 건수 · 판정 `오탐(+n개)` / `미탐(-n개)`

## 용어 (9월~)

| 표시 | 의미 |
|---|---|
| 미탐 (FN) | 수기 검토필요 · AI 검토불필요 |
| 오탐 (FP) | 수기 검토불필요 · AI 검토필요 |
| reviewNeededDiff | AI 검토필요 항목 수 − 수기 검토필요 항목 수 |
| 수기 최종 | 감안 후 Cold/Hot. 매트릭스에 넣지 않음 |

8월 검수는 `reviewNeeded`가 없어 백필한다. Hot+코멘트 `감안`=검토필요·최종 Hot, Hot만=검토불필요, Cold=검토필요·최종 Cold.
